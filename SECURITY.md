# Security policy

## Supported versions

Security fixes are provided for the latest release on the default branch. Older releases and prereleases may not receive fixes. Upgrade to the newest available release before reporting an issue when practical.

## Privately reporting a security vulnerability

Do not open a public issue, discussion, or pull request for a suspected vulnerability.

Use [GitHub private vulnerability reporting](https://github.com/moodiness/hermes-plugins/security/advisories/new) so maintainers can investigate in private. Include affected versions, impact, reproduction steps or a proof of concept, and any suggested remediation. If private vulnerability reporting is unavailable, contact the repository owner through their GitHub profile and ask for a private reporting channel; do not include vulnerability details in that initial message.

You should receive an acknowledgement within 7 days and a status update within 14 days. Timelines for a fix depend on severity and complexity.

## Coordinated disclosure

Please keep the report confidential until a fix and advisory are ready. The maintainers will validate the report, coordinate remediation and release timing, and credit reporters who request attribution. We aim to disclose after affected users have a reasonable opportunity to update. If we cannot agree on a timeline, communicate before publishing details.
